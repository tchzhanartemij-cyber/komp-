## Контракт: один источник на каждый тип данных

| Данные | Источник истины | Кто пишет | Как агент читает в новой сессии любого канала |
| --- | --- | --- | --- |
| Факты о людях/местах/проектах | `life/memory/<Имя>.md` | Сводка (`/api/memory/add`) и агент (навык life-ledger) | Прямое чтение страницы + поиск по ключевым словам по `life/memory/` (навык) |
| Профиль, предпочтения, «кто ты» | `USER.md`/`SOUL.md` рабочего пространства | Только агент | Загружается OpenClaw в начале сессии; панель не читает и не правит |
| Долгая память агента | `MEMORY.md`, `memory/*.md`, индекс `memory_search` | Агент / dreaming | `memory_get`; `memory_search` сейчас **не работает** (см. ниже) |
| Переписка | канонический сеанс задачи 12 (`sessions_history`) | Telegram, Сводка, голос | Не копируется в память; сырой транскрипт панель в память не пишет |

Голос (задача 11) идёт к агенту как обычная реплика — факт из голоса пишет агент
по навыку в тот же `life/memory/`. Отдельного «голосового» хранилища нет.

## Что изменено

- `POST /api/memory/add`: свежее чтение страницы прямо перед записью; запись
  дозаписью в конец (чужие строки агента не затираются; если агент атомарно
  заменил файл в этот момент — read-after-write не находит строку → 409, без
  тихой потери); проверка после записи (`verified`, `version` = sha256[:16]
  файла, номер строки); идемпотентность по `request` (ретрай → `duplicate:true`,
  без второй записи); дедуп одинакового текста; отказ (400) для секретов,
  `<think>/<reasoning>/<system>`, «system prompt / системный промпт».
- Журнал `dashboard-agent/memory-audit.jsonl` (только дозапись): время, операция
  add/dedup/delete, источник, request, страница, строка, sha256 текста, версии
  до/после. Сам текст факта в журнал не пишется.
- `POST /api/memory/delete`: удалённая строка сначала дописывается в
  `dashboard-agent/memory-removed.md` — история не теряется.
- `GET /api/memory/status`: число страниц/фактов, версия хранилища, запись
  возможна, последняя запись журнала, режим поиска (`keyword`, `semantic:false`
  с причиной), контракт. `?probe=1` (только при защищённой панели и включённой
  «Переписке» задачи 12) — реальный вызов `/tools/invoke` для `memory_get`
  (`MEMORY.md`, 1 строка) и `sessions_history` (limit 1): возвращаются только
  ok/фиксированная причина/мс, содержимое отбрасывается. `memory_search`
  намеренно не вызывается: при текущей конфигурации запрос может уйти в платный
  embedding-провайдер.
- UI: в карточке «Граф памяти» — раскрывашка «Как агент видит память» и кнопка
  «Проверить инструменты»; форма памяти шлёт request id и показывает «Такой факт
  уже есть — не дублирую».
- Навык `openclaw/skills/life-ledger/SKILL.md` (в репозитории, установленная
  копия не менялась): дедуп перед записью, не хранить системные инструкции,
  рассуждения и сырые куски переписки, поиск по ключевым словам назван честно,
  `life/memory/` — источник фактов для всех каналов.

## Подтверждено vs заблокировано

Подтверждено (код + тесты, изолированно): запись факта из Сводки с
read-after-write, без дублей при ретраях, с журналом происхождения и версиями;
сохранность параллельных правок агента; отказ хранить секреты/служебный текст;
честная диагностика режима поиска и доступности инструментов.

Не подтверждено вживую / заблокировано:

1. **Живая сквозная приёмка** (факт из Сводки → новая сессия Telegram/другого
   канала находит его → один безвредный tool/делегирование). Настоящий агент
   читает production `~/.openclaw/workspace/life`, а по распоряжению владельца
   тесты 13 не пишут в боевые данные и не используют 8787. Изолированный
   `LIFE_DIR` агенту не виден, поэтому живой recall в изоляции невозможен —
   подменять его мок-данными не стал. Нужен отдельный допуск: одна синтетическая
   страница `life/memory/Т13 тест.md` в боевом life (удаляется после) +
   одноразовая сессия `agent:main:svodka-t13-*`, или отдельное тестовое
   рабочее пространство агента.
2. **Семантический поиск**: `memory_search` отключён — индекс fts-only, конфиг
   ожидает `text-embedding-3-small`. Исправление только через первоклассный
   инструмент конфигурации OpenClaw; в этой сессии (Claude Code-воркер) такого
   инструмента нет, ручная правка JSON/CLI/DB запрещена. Подготовленный запрос
   для основного агента (из `diagnostics/server-optimization-20261029/RECALL-PASS2.md`):
   «Через первоклассный инструмент конфигурации openclaw перечитать схему и
   авторские поля; сохранить соседние поля и переопределения агентов; задать
   ТОЛЬКО эффективное `memory.search.provider = "none"` для main (top-level
   `memory.search` или override main); не трогать `agents.defaults.memorySearch`,
   не ставить `fallback`, не пересобирать индекс, не ставить провайдеров;
   снять исходное значение для отката; при отказе адаптера вернуть точную ошибку
   валидации». После этого: `openclaw memory status` → provider none, fts-only;
   запросы «Monotonica», «голосовой помощник» должны находиться. Это даст
   поиск по ключевым словам (FTS), **не** семантику. Семантика — отдельное
   решение о расходах/локальной модели (~0.3 ГБ, RAM при 8 ГБ+4 ГБ swap).
   Кроме того, `life/memory/` не входит в индекс `memory_search` по умолчанию;
   добавление `extraPaths` — тоже отдельная правка конфигурации через тот же
   инструмент.
3. Probe инструментов работает только после включения «Переписки» задачи 12
   (`SVODKA_CANONICAL_SESSION`, `SVODKA_WORKSPACE_ENABLED=1`) в установке 11+12.
4. Физический iPad, Telegram WebView — не проверялись. Opus-авторизация в
   маршрутах — не подтверждена этой задачей.
