# Задача №10: единая консоль и управляемая команда — brief и фазы

Основа: принятая база `claude/eager-mendel-oncysb` 08a18c8 (№8, офис). Ветка `jarvis/task-10`.
Источник требований: gap-audit 2026-10-28 и кадры 01–14 второго видео (только кадры/субтитры,
аудио не транскрибировано; рекламные claims — не спецификация, «Hermes» — название из ролика,
не зависимость и не повод для миграции).

## Что уже было и переиспользуется (не дублируется)
- Оркестрация «руководитель → исполнитель → проверка» уже существует штатно: раннер кодера
  (`openclaw/coder/coder.py`) запускает Claude Code с allow/deny-листом инструментов, который
  делегирует объёмный код в `codex exec -s workspace-write`; итог проверяет владелец
  (`принять`/`переделать` в Telegram), статусы, отмена, ожидание ответа и лимита — в очереди.
  Свой исполнитель, обход прав или approve-all не добавлялись.
- Офис №8 (`office.py`, `/api/office`) уже читает очередь кодера read-only через backend
  (`SVODKA_CODER_QUEUE_FILE`) с редактированием названий; сырые логи и `tasks.json` в браузер не
  отдаются.
- Агент `/v1/responses` (`agent.py`) — настоящий агент шлюза; чат ИИ — `claude -p --tools ''`,
  т.е. **чат без инструментов, не агент**. Выбор модели в чате не маршрутизирует агента.

## Срез 1 (сделан в этой ветке)
1. Явный выбор Claude Opus / Sonnet / Haiku в чате (псевдонимы CLI `opus`/`sonnet`/`haiku`)
   вместо только «по умолчанию CLI». Фактическая модель берётся из stream-json Claude
   (`system/init.model`, `assistant.message.model`) и показывается отдельно от запрошенной;
   несовпадение (например, запрошен Opus, ответил Sonnet) помечается предупреждением.
   Доказательство — только `ai/model-proof.json` (последний реальный ответ/ошибка по каждому
   выбору); перечисление из кэша Codex/настроек OpenClaw остаётся «не проверено».
2. `/api/team` (read-only, та же авторизация, что `/api/office`): по каждой задаче кодера —
   статус/исход (в т.ч. «ждёт принятия владельцем», «ждёт ответа», «ждёт лимит», «отменено»,
   «ошибка»), роли: Руководитель (Claude Code, фактическая модель из лога), Исполнитель (Codex:
   сколько вызовов замечено и с какими моделями), Проверка (владелец; отдельный Opus-рецензент
   честно помечен «не настроен»). Без текста задач, результатов, сессий, путей, процентов.
3. Блок «Команда» в разделе офиса: связывает задачу с персонажем офиса («Показать в офисе»),
   бизнес-роли из ролика (Контент, Продажи, Аналитика…) явно «не подключены».

## Чего срез 1 НЕ делает (осознанное урезание)
- Не задаёт модель раннеру кодера (`--model opus`): это глобальная смена поведения раннера —
  нужна отдельная команда владельца. Сейчас руководитель работает на модели по умолчанию CLI,
  и это видно в «Команде» как «запрошено: по умолчанию», «фактически: <из лога>».
- Opus-review настоящим не является: отдельного рецензента нет; Opus auth/fallback на этой
  машине не проверен живым запуском (blocker из аудита). Sol/GPT-проверку за Opus не выдаём.
- Маршрутизация модели для агента `/v1/responses` per-run не делается: модель определяет
  конфигурация шлюза; менять Gateway/auth/config без согласования нельзя.

## Backlog фаз (план, не готовый функционал)
- **Ф2. Управляемая команда, запуск из консоли.** Постановка задачи кодеру из панели через
  штатный `coder add` (а не свой исполнитель) с CSRF/origin/token; выбор модели руководителя
  per-run — только после решения владельца менять раннер (флаг `--model` на задачу,
  allowlist opus/sonnet/haiku, запись requested/actual). Отдельная роль рецензента: второй
  штатный запуск Claude Code `--model opus` read-only по диффу ветки с явным «blocked»,
  если Opus недоступен. Нужно решение: разрешить ли менять `coder.py`.
- **Ф3. Импорт PDF/изображений в память.** MIME/size-лимиты, provenance (имя, sha256, дата),
  предпросмотр и подтверждение перед дописыванием в существующие страницы памяти, без
  перезаписи. Текст PDF — только если локально уже есть `pdftotext` (poppler); изображения —
  без OCR, только превью + ручная подпись, пока не выбран локальный OCR. Содержимое файлов —
  данные, не инструкции (prompt injection не исполняется). Внешним сервисам не отправлять.
- **Ф4. Вечерний отчёт и артефакты.** Кнопка «отчёт за день» по реальным задачам/планам/
  запускам (подсчёт по записям, без выдуманных процентов); черновик контент-плана/результат
  исследования сохраняется как артефакт задачи. Регулярность — только через инструмент
  автоматизаций после отдельного решения о частоте, не через файлы расписаний.
- **Ф5 (gated). Почта, внешний календарь, соцсети.** Сейчас: not-connected. Нужны выбор
  аккаунтов и scopes: почта — read-only (например, Gmail `gmail.readonly`), календарь —
  `calendar.readonly`, соцметрики — read-only insights. Отправка, бронирование, публикации —
  только с отдельным подтверждением. Текущий недельный календарь строится из сроков задач и
  **не является** интеграцией Google Calendar.
- **Совместимость с №9 (голос).** №9 (origin/jarvis/task-9, f5bd5f2) не входит в эту ветку.
  Срез 1 не трогает `/api/agent/send`, `same_origin`, голосовые маршруты; новый маршрут
  добавлен рядом с `/api/ai/models`, чтобы не конфликтовать с правками №9 в `do_GET`/`do_POST`.
